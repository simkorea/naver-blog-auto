# 증거파인더 — 사용 설명서

녹음·카톡·문서·사진에서 **필요한 말을 찾아내고, 어디에 있는지 짚어주고,
제출할 수 있는 형태로 만들어 주는** 프로그램입니다.

---

## 이 프로그램이 하는 일

1. **찾기** — "환불" 같은 단어로도, "고객이 계약을 인정하는 뉘앙스" 같은
   문장으로도 검색합니다.
2. **짚어주기** — "이 파일 12분 34초부터 13분 02초까지"를 알려줍니다.
   원본을 그대로 넘겨도 받는 사람이 바로 그 지점을 찾습니다.
3. **말 바뀐 곳 잡아내기** — 상대방이 먼저 인정했다가 나중에 부인한 대목을
   자동으로 찾아냅니다.
4. **법 조문 붙이기** — 관련 법령·판례를 법제처에서 실제로 받아와 붙입니다.
5. **제출 패키지 만들기** — 원본·발췌본·증거목록·재생안내서를 한 폴더로.

---

## ⚠ 먼저 알아두실 것

**녹음의 적법성**
본인이 대화에 참여한 녹음은 적법하게 증거로 쓸 수 있습니다. 그러나
**제3자 간 대화를 몰래 녹음한 것은 통신비밀보호법 위반**으로 증거능력이
부정되고 처벌 대상이 됩니다. 자료 등록 시 반드시 구분해 주세요.
'아니오'로 표시한 자료는 검색 결과와 제출물에서 자동으로 빠집니다.

**AI 전사는 틀릴 수 있습니다**
한국어 음성 인식은 완벽하지 않습니다. 이 프로그램은 두 개의 모델로
따로 받아 적어 대조하고, 갈리는 구간을 '확인 필요'로 표시합니다.
**제출할 구간은 반드시 원본을 들어 확인**하시고 '귀로 확인함'을 체크하세요.
확인하지 않은 구간은 모든 문서에 '미검증'으로 표시됩니다.

**발췌본만 내지 마세요**
유리한 구간만 잘라 발췌본만 제출하면 "맥락을 잘라내 편집했다"는 반박을
받습니다. 이 프로그램은 **원본 없이는 패키지를 만들지 않습니다.**
원본과 함께 내고 대응표를 붙이면, 발췌본은 편집물이 아니라
"여기를 들으세요"라는 안내가 됩니다.

**법률 자문이 아닙니다**
법률 코멘트 기능은 관련 조문·판례를 찾아주는 조사 보조입니다.
법리 판단과 대응 전략은 반드시 변호사와 상의하세요.

## 설치 — 가장 쉬운 방법

`evidence` 폴더의 **`설치.bat` 을 더블클릭**하세요. 나머지는 알아서 합니다.

- 그래픽카드가 있으면 GPU 빌드를, 없으면 CPU 빌드를 알아서 골라 깝니다.
  (이걸 사람이 하면 틀리기 쉽습니다 — 그냥 `pip install torch` 하면 GPU가
  있어도 CPU 빌드가 깔려서 전사가 10배 느린데 원인을 모릅니다)
- 끝나면 AI 모델을 미리 받아둘지 물어봅니다. **받아두시길 권합니다.**
  한 번 받으면 이후에는 인터넷 없이 동작하고, 급할 때 기다리지 않아도 됩니다.

파이썬이 없다고 나오면:
[python.org](https://www.python.org/downloads/)에서 3.10 이상을 받아 설치하되,
설치 화면에서 **"Add Python to PATH"에 반드시 체크**하세요.

### 명령으로 하고 싶다면

```
python evidence/setup_check.py            설치 상태만 점검
python evidence/setup_check.py --install  부족한 것 설치
python evidence/setup_check.py --models   AI 모델 미리 받기 (약 4GB)
```

`setup_check.py`는 무엇이 빠졌고 그게 없으면 **어떤 기능을 못 쓰는지**까지
알려줍니다.

### 바로가기 파일

`evidence` 폴더 안에 있습니다. 더블클릭하면 됩니다.

| 파일 | 하는 일 |
|---|---|
| `설치.bat` | 필요한 것 설치 (그래픽카드 자동 감지) |
| `실행.bat` | 프로그램 시작 |
| `백업.bat` | 분석 결과 백업 |
| `무결성확인.bat` | 원본이 그대로인지 확인 |

### 내려받기

GitHub `simkorea/naver-blog-auto` → 브랜치를
`claude/file-voice-analysis-program-lb7qi8` 로 바꾸고 → **Code → Download ZIP**.

압축을 풀 때 **경로에 한글이나 공백이 있어도 괜찮습니다.**
(`C:\Users\사용자\바탕 화면\` 같은 경로도 동작하게 만들었습니다)

## 설치 후 순서

```
python evidence/setup_check.py --token      인증키 입력 (물어보고 대신 써줍니다)
python evidence/setup_check.py --models     AI 모델 받기 (약 4GB)
python evidence/setup_check.py --selftest   전 과정 점검 (3분)  ← 중요
```

**`--selftest`를 꼭 돌려보세요.** 가짜 사건을 만들어 스캔·전사·화자분리·검색·발췌·
제출 패키지까지 전 과정을 실제로 돌려봅니다. 실제 자료와 분석 결과는 건드리지 않습니다.

여기서 통과하면 실제 자료를 믿고 넣을 수 있고, 막히면 아직 아무것도 잃지 않은
상태에서 고칠 수 있습니다. 소송 자료를 넣고 몇 시간 돌린 뒤에 막히면 그 시간이
통째로 날아갑니다.

전사 속도도 알려줍니다 — "1시간 녹음이면 대략 몇 분" 이 나오므로,
밤새 돌릴지 나눠 돌릴지 판단하실 수 있습니다.

## 인증키 발급 (선택)

두 가지 기능에만 필요합니다. 없어도 나머지는 전부 동작합니다.

### 화자 분리 (누가 말했는지 구분) — HuggingFace 토큰
1. https://huggingface.co 가입
2. 우측 상단 프로필 → **Settings → Access Tokens → New token**
   (Type: Read) → 복사
3. https://huggingface.co/pyannote/speaker-diarization-3.1 접속 →
   **이용 약관에 동의** (이걸 안 하면 토큰이 있어도 안 됩니다)

### 법률 코멘트 — 법제처 인증키
1. https://open.law.go.kr 접속 → 로그인
2. **OPEN API → 활용신청** (무료, 즉시 발급)

### .env 파일에 넣기
프로그램 폴더에 `.env` 파일을 만들고(메모장으로 새 파일 저장, 파일명 `.env`):
```
HF_TOKEN=발급받은_허깅페이스_토큰
LAW_OC=발급받은_법제처_인증키
```

## 사용 순서

### ① 자료 등록
증거 폴더 경로를 넣고 **스캔 시작**.
- 하위 폴더까지 전부 훑습니다.
- 같은 파일을 여러 곳에 복사해 두었어도 한 건으로 묶습니다.
- 각 파일의 SHA-256 해시를 기록합니다(나중에 "이 파일이 그때 그 파일"임을 증명).
- **원본은 읽기만 하고 수정·이동하지 않습니다.**

녹음 파일마다 **"내가 참여한 대화인가?"**를 지정하세요. 이게 가장 중요합니다.

### ② 분석 실행
**1단계 텍스트 자료**를 먼저 돌리세요. 금방 끝나고 바로 검색할 수 있습니다.

**사건 고유명사 사전**을 채우면 인식률이 눈에 띄게 좋아집니다.
녹음에 나오는 사람 이름, 상호, 단지명을 적어주세요.

그다음 **2단계 녹음 전사**. 시간이 걸리니 켜 두고 다른 일을 하셔도 됩니다.
중간에 껐다가 다시 켜면 남은 것부터 이어서 합니다.

### ③ 화자 지정
'화자1', '화자2'가 각각 누구인지 지정합니다.
대표 발화를 들어보고 **'나'**, **'상대방'**을 고르세요.
이걸 해야 "상대방이 한 말만" 골라볼 수 있습니다.

### ④ 검색
- 단어로: `환불`, `설명 들었`, `계약금`
- 문장으로: `고객이 계약을 인정하는 뉘앙스`
- **확인 필요 구간만** 체크하면 전사가 의심스러운 곳만 봅니다. 여기부터 들으세요.

결과를 클릭하면:
- **🔊 이 지점 듣기** — 원본이 그 지점부터 재생됩니다 (맥락 위해 5초 앞부터)
- 들어본 뒤 **'전사 내용이 실제 음성과 같음'** 체크
- 다르면 실제 말한 내용을 적어주세요. 그게 문서에 반영됩니다.
- **📎 발췌 담기** — 제출할 구간으로 담습니다

### ⑤ 타임라인
**★ 진술이 바뀐 정황**을 먼저 보세요. 상대방이 먼저 인정했다가
나중에 부인한 대목을 찾아 나란히 보여줍니다.

`evidence/keywords.yaml` 파일을 메모장으로 열면 찾을 표현을 직접 고칠 수 있습니다.
**불리한 표현도 꼭 넣으세요.** 상대가 뭘 들고 올지 미리 알아야 방어가 됩니다.

### ⑥ 법률 코멘트
1. `evidence/law_scope.yaml`에서 받아올 법령을 정합니다
2. **법령·판례 받아오기** — 법제처에서 원문을 내려받습니다
3. **코멘트 만들기** — 각 발언에 관련 조문·판례를 붙입니다

모든 조문·판례는 법제처에서 다시 조회해 **실존을 확인한 것만** 표시됩니다.
확인되지 않은 인용은 차단되고, 무엇이 걸러졌는지 따로 보여줍니다.

### ⑦ 제출 패키지
발췌 목록을 확인하고 **제출 패키지 만들기**.

```
제출_20260825_경찰서/
├── 00_증거목록.xlsx        번호·해시·일시·쟁점·요지
├── 01_재생안내서.docx      어느 파일 몇 분 몇 초를 들으면 되는지
├── 02_녹취록발췌.docx      화자·타임코드 + 앞뒤 맥락
├── 03_해시목록.txt         원본·발췌본 SHA-256
├── README_먼저읽어주세요.txt
├── 원본/                   무수정 복사본
└── 발췌본/                 잘라낸 구간
```

이 폴더를 통째로 USB에 담아 제출하시면 됩니다.

### ⑧ 도구

**백업** — 전사 결과·청취 확인 기록·화자 지정·발췌 목록을 파일 하나로 저장합니다.
여기 쌓이는 것은 다시 만들기 어렵습니다. 몇 시간 걸린 전사, 일일이 들어가며
확인한 청취 기록, 손으로 고친 화자 지정. **중요한 작업을 마칠 때마다 눌러두세요.**
복원할 때는 지금 상태를 자동으로 한 번 더 백업하므로 되돌릴 수 있습니다.

**내보내기**
- 전체 전사본 (워드/텍스트) — 녹음 하나를 처음부터 끝까지
- 전체 구간 표 (엑셀/CSV)
- 타임라인 (HTML) — 브라우저로 보는 시간순 정리

**정리** — 전처리 임시 사본과 오래된 백업을 지웁니다. 원본과는 무관합니다.

**처리 이력** — 언제 무엇을 어떤 설정으로 처리했는지 기록입니다.
지워지지 않고 계속 쌓이며, 자료를 어떻게 다뤘는지 보여주는 근거가 됩니다.

## 자주 겪는 문제

**"카톡 대화가 중간에 잘려요"**
카카오톡은 대화가 길면 파일을 1MB마다 쪼갭니다
(`KakaoTalk_Chats.txt`, `KakaoTalk_Chats_2.txt`…).
이 프로그램은 자동으로 이어 붙이므로, **쪼개진 파일을 모두 같은 폴더에**
두시면 됩니다.

**"한글(.hwp) 파일을 못 읽어요"**
구형 한글 파일은 읽기 어렵습니다. 한글 프로그램에서 열어
**다른 이름으로 저장 → hwpx** 또는 **PDF로 저장** 후 다시 등록하세요.

**"녹음 전사가 너무 느려요"**
GPU가 없으면 느립니다. [분석 실행] 탭에서 **이중 모델 교차 검증**을 끄면
시간이 절반으로 줍니다. 다만 전사 신뢰도 표시가 약해집니다.

**"모델을 내려받지 못했습니다"**
회사망이나 공용 와이파이는 huggingface.co를 막는 경우가 있습니다.
다른 네트워크(집 와이파이, 휴대폰 테더링)에서 한 번만 받아두면
이후에는 인터넷 없이 동작합니다:
```
python evidence/setup_check.py --models
```

**"스캔한 계약서가 검색이 안 돼요"**
글자가 그림으로 들어 있는 PDF도 이제 자동으로 읽습니다.
다만 인식이 흐릿하면 '확인 필요'로 표시되니, 그런 항목은
원본 PDF를 직접 눈으로 확인하세요.

**"통화 녹음 전사가 부정확해요"**
[분석 실행] 탭의 **음성 전처리**를 '세게'로 바꿔보세요.
잡음을 줄이고 음량을 고르게 맞춘 뒤 전사합니다.
그리고 **사건 고유명사 사전**에 사람 이름·상호·단지명을 꼭 넣으세요.
이게 인식률에 가장 크게 영향을 줍니다.

**"의미 검색이 안 돼요"**
`pip install sentence-transformers` 를 실행하세요.
첫 실행 때 모델을 내려받느라(약 2GB) 시간이 걸립니다.
설치하지 않아도 단어 검색은 정상 동작합니다.

**"화자 분리가 안 돼요"**
`.env`의 `HF_TOKEN`과, HuggingFace에서 모델 이용 약관 동의를
모두 확인하세요. 둘 중 하나만 빠져도 동작하지 않습니다.
